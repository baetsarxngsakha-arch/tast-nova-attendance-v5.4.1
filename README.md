# NOVA HR · เวอร์ชัน 5.4.2.3

โครงสร้าง: Google Sheets เป็นฐานข้อมูล, Apps Script เป็น API, `public/` เป็นหน้าเว็บสำหรับ Netlify และ GitHub ใช้เก็บซอร์สโค้ด

## ติดตั้งหรืออัปเกรด

1. เปิด Google Sheet `Nova.3` → **ส่วนขยาย → Apps Script**
2. ใส่ไฟล์ `.gs` ทั้ง 8 ไฟล์ใน `apps-script/` ลงในโปรเจกต์ Apps Script เดียวกัน: `Setup.gs`, `Util.gs`, `Code.gs`, `Attendance.gs`, `Leave.gs`, `Users.gs`, `Face.gs`, `Calendar.gs` แล้วบันทึก
3. เรียก `setupAll()` จาก Apps Script editor และอนุญาตสิทธิ์ ฟังก์ชันนี้สร้างชีตที่ขาดให้อัตโนมัติและรันซ้ำได้
4. ตรวจชีต `FaceTemplates`: คอลัมน์ **เวกเตอร์ใบหน้า (128 ค่า JSON)** จะมีข้อมูลเมื่อ Admin ลงทะเบียนสำเร็จ เวอร์ชัน 5 พยายามย้ายเวกเตอร์เดิมจาก Script Properties ของ **โปรเจกต์ Apps Script เดิม** ไปชีตนี้ขณะรัน `setupAll()` หากใช้โปรเจกต์ใหม่หรือเวกเตอร์เดิมหาย ต้องลงทะเบียนใบหน้าใหม่
5. Deploy Apps Script เป็น Web App โดยเลือก **เรียกใช้ในฐานะ: ฉัน** และ **ผู้มีสิทธิ์เข้าถึง: ทุกคน** เมื่อแก้โค้ดเดิมให้สร้างเวอร์ชัน Deploy ใหม่ คัดลอก URL `/exec`
6. นำเนื้อหา `public/` ขึ้น Netlify (`netlify.toml` กำหนด publish directory ไว้แล้ว) ตั้ง URL `/exec` ในหน้าเข้าสู่ระบบ หรือใน `public/js/config.js` ก่อนเผยแพร่ ห้ามใส่ PIN หรือ token ในไฟล์นี้

`setupAll()` สร้าง Users, Accounts, FaceTemplateIndex, **FaceTemplates**, CalendarDays, Attendance, Config, Shifts, LeaveTypes, LeaveRequests, AuditLog และชีตประกอบอื่น ๆ โดยไม่ลบแถวที่มีอยู่ PIN ครั้งแรกของ OWNER และรหัสผ่าน Developer อยู่ในผลลัพธ์/บันทึกของ `setupAll()` เพียงครั้งเดียว ให้เก็บไว้และเปลี่ยนรหัส Developer เมื่อเข้าสู่เครื่องมือครั้งแรก หาก PIN OWNER หายให้เรียก `resetOwnerPin()` ใน editor

## การสแกนและลงเวลา

- เปิดเว็บแล้วพบหน้าสแกนทันที กล้องจะพยายามเปิดเอง หากเบราว์เซอร์ขอการกดจากผู้ใช้ ให้กด **เริ่มสแกนใบหน้า**
- เมื่อเปิดกล้อง ระบบนับถอยหลังก่อนเริ่มตรวจใบหน้า ค่าเริ่มต้น **5 วินาที** และ OWNER ปรับได้ 0–15 วินาทีในหน้า **ตั้งค่าระบบ → LOCATION** เมื่อสแกนทั้งหน้าแรกและหน้าสแกนหลังล็อกอิน ระบบเทียบเวกเตอร์กับ `FaceTemplates` แล้วแสดงชื่อเล่นให้ตรวจ กด **ใช่ ฉันเอง** จึงบันทึกเข้างานหรือออกงาน; กด **ไม่ใช่ · สแกนใหม่** จะไม่บันทึกและเปิดกล้องใหม่ รายการยืนยันมีอายุ 2 นาทีและใช้ได้ครั้งเดียว หลังบันทึกสำเร็จกรอบภาพเป็น **สีเขียว** และมีเสียงบี๊บ เมื่อไม่สำเร็จกรอบเป็น **สีแดง** พร้อมข้อความสาเหตุ
- สแกนใบหน้าได้ตลอด **24 ชั่วโมง** ตามเวลา Asia/Bangkok และสแกนได้หลายรอบในหนึ่งวัน ระบบสลับ **เข้า → ออก → เข้า → ออก** โดยแต่ละคู่เก็บเป็นรายการแยกใน Attendance การออกงานข้ามเที่ยงคืนปิดรายการที่เปิดค้างอยู่
- `setupAll()` ซ่อมคอลัมน์ **สาย (นาที)** ของแถวเดิมที่เป็น `#NUM!` หรือค่าว่าง โดยคำนวณจากเวลาเข้าและกะ และกำหนดรูปแบบตัวเลขเป็นจำนวนเต็ม
- เวลาสายเก็บเป็นจำนวนเต็มนาที: ถ้าไม่สายเป็น `0` ถ้าช้ากว่าเวลาเริ่มกะให้นับนาทีที่เกิน ไม่มีการหักนาทีผ่อนผันในเวอร์ชัน 5
- ระบบพูด **ชื่อเล่นที่เป็นภาษาไทยเท่านั้น** หลังยืนยันและบันทึกสำเร็จ: ก่อน 09:00 “คุณ[ชื่อเล่น] ยินดีต้อนรับ”; ตั้งแต่ 09:00 “คุณ[ชื่อเล่น] เข้างานสายนะครับ”; เมื่อออก “คุณ[ชื่อเล่น] ออกงาน บ๊ายบาย” เลือกเสียงไทยผู้ชายจากเสียงที่อุปกรณ์มี หากชื่อเล่นไม่มีอักษรไทยจะใช้ส่วนภาษาไทยของชื่อเต็ม และหากไม่มีชื่อภาษาไทยเลยจะพูดเฉพาะข้อความสถานะ และลดความเร็วให้อ่านชัด หากอุปกรณ์ไม่มีเสียงไทยผู้ชาย ระบบใช้เสียงไทยที่มีพร้อมปรับโทนให้ต่ำลง กด **เปิดเสียงบนเครื่องนี้** หากเบราว์เซอร์ยังไม่อนุญาตเสียง
- โมเดลใบหน้าจะโหลดล่วงหน้าและใช้ตัวอย่างใบหน้า 1 ครั้งสำหรับการลงเวลา (ลงทะเบียนยังใช้ 2 ครั้ง) Apps Script แคชรายการใบหน้าชั่วคราว 5 นาทีและล้างแคชเมื่อข้อมูลพนักงานหรือใบหน้าเปลี่ยน
- หากหน้าสแกนไม่ได้ใช้งาน 30 วินาที ระบบแสดงนาฬิกาดิจิทัลแบบสมาร์ทวอชเต็มพื้นที่หน้าเว็บ แสดงเวลาและวันที่ไทยแบบสด แตะเพื่อกลับมาสแกน ระหว่างกำลังสแกนหรือรอยืนยันตัวตนจะไม่พักหน้าจอ การพักนี้ไม่สั่งปิดจออุปกรณ์ และเบราว์เซอร์ยังควบคุมการแสดงแถบเครื่องมือของตน

- OT อัตโนมัติ 1.5x เริ่มนับจาก **เวลาสิ้นสุดกะ** ในชีต Shifts (เช่น กะ 09:00–18:00 เริ่ม OT หลัง 18:00) เวลาเข้าก่อนเริ่มกะไม่สร้าง OT โดยตัวเอง OWNER/Admin ยังแก้นาทีสาย กะ และชั่วโมง OT ทุกอัตราในรายการลงเวลาได้โดยไม่มีเพดานชั่วโมงตามสูตรอัตโนมัติ การแก้ OT 1.5x จะปิดการคำนวณอัตโนมัติในแบบฟอร์มนั้น และต้องระบุเหตุผลเพื่อบันทึก AuditLog
- หน้าสแกนแรกแสดงนาฬิกาวงกลมพร้อมวันและเวลาปัจจุบันตามเวลาไทย

## Admin และพนักงาน

- OWNER เปลี่ยนชื่อบริษัทและอัปโหลดโลโก้ใน **ตั้งค่าระบบ → ชื่อและโลโก้บริษัท** ภาพถูกย่อก่อนเก็บใน Config และแสดงร่วมกันทุกเครื่อง
- ฟอร์มเพิ่มพนักงานเติมรหัส NV ตามลำดับให้อัตโนมัติ แต่ Admin พิมพ์แก้ได้ และเลือก **กะปกติ** ไว้เป็นค่าเริ่มต้น
- Admin ทุกคนกดชื่อใน **ตั้งค่าระบบ → EMPLOYEES** เพื่อดูข้อมูล ประวัติการลงเวลาและวันลา และแก้ชื่อ ชื่อเล่น แผนก กะของพนักงานได้ การแก้สิทธิ์ Admin ของหัวหน้าแผนกจำกัดเฉพาะ OWNER
- Admin ลงทะเบียนใบหน้าใน **FACE REGISTRATION** โดยเลือกพนักงานและสแกน ไม่ต้องติ๊กช่องรับทราบ หน้าพนักงานแสดงสถานะว่าเก็บใบหน้าสำเร็จหรือไม่ ก่อนลบเวกเตอร์มีหน้าต่างยืนยันและขอเหตุผล
- การลบพนักงานเป็นการปิดบัญชี ลบเวกเตอร์ใบหน้า และคงประวัติงานไว้
- Admin เปิดหน้าหลักแล้วเห็นภาพรวมพนักงาน ประวัติการลงเวลา และวันลาทั้งหมดโดยไม่ต้องเปิดแต่ละรายการ หน้า **ประวัติและรายงาน** แสดงฟอร์มแก้ไข 22 หัวข้อของรายงาน โดยแก้วันที่ เวลา กะ นาทีสาย หมายเหตุ และแยก OT 1.0/1.5/2.0/3.0 พร้อมเหตุผลได้ ข้อมูลพนักงาน การลา วันหยุด และวันหยุดบริษัทแสดงจากรายการต้นทางในช่องอ่านอย่างเดียว หลังแก้ต้องอนุมัติใหม่ ค่า OT เริ่มต้นยังลงที่ 1.5x และคำนวณใหม่เมื่อเปลี่ยนเวลาโดยเลือกช่องคำนวณอัตโนมัติ หัวหน้าแผนกและ OWNER แก้ได้; OWNER ลบรายการลงเวลาได้โดยมีเหตุผลบันทึกใน AuditLog
- พนักงานและหัวหน้าแผนกยื่นคำขอลาได้ OWNER ไม่ยื่นคำขอลา หัวหน้าแผนก/OWNER พิจารณาคำขอได้ Admin เพิ่มและแก้ LeaveTypes ได้ในหน้าตั้งค่า
- ในหน้าปฏิทิน พนักงานและหัวหน้าแผนกยื่นคำขอลาด้วยวันเริ่มและวันสิ้นสุดได้ คำขอวันหยุดก็ใช้วันเริ่มและวันสิ้นสุดในคำขอเดียว โดยปฏิทินแสดงทุกวันที่อยู่ในช่วงนั้น
- พนักงานขอวันหยุดได้เฉพาะตนเอง คำขอจะอยู่ในสถานะรออนุมัติจนหัวหน้าแผนกหรือ OWNER พิจารณา Admin สามารถกำหนดวันหยุดให้ผู้อื่นได้ พนักงานแก้หรือยกเลิกคำขอวันหยุดของตนเองได้ และแก้หรือยกเลิกวันลาของตนเองได้ เมื่อแก้รายการที่เคยอนุมัติแล้วต้องรออนุมัติใหม่
- ปฏิทินแสดงเฉพาะชื่อในสีสถานะ: เขียว = มาทำงาน, แดง = วันหยุดที่อนุมัติแล้ว, เทา = ลาที่อนุมัติแล้ว วันที่ไม่มีรายการยังไม่กำหนดสถานะ
- OWNER เปิดหรือปิดการบังคับตรวจโลเคชันใน **ตั้งค่าระบบ → LOCATION** ค่าเริ่มต้นคือเปิด เมื่อปิด พนักงานสแกนจากทุกที่ได้ และระบบไม่ขอพิกัดขณะลงเวลา
- Admin ตั้งค่าพิกัดละติจูด ลองจิจูด และรัศมีใน **ตั้งค่าระบบ → LOCATION** (Config: `Target Latitude`, `Target Longitude`, `Allowed Radius (KM)`) ระบบขอตำแหน่ง GPS และตรวจว่าอยู่ในรัศมีก่อนเปิดกล้อง รวมทั้งตรวจซ้ำที่ Apps Script ขณะเทียบใบหน้าและก่อนบันทึกเวลา หากปิดสิทธิ์ตำแหน่ง ตำแหน่งคลาดเคลื่อนเกินรัศมี หรืออยู่นอกพื้นที่ ระบบจะไม่บันทึกเวลา ควรตั้งพิกัดสถานที่ทำงานจริงก่อนเผยแพร่
- Admin โหลดและส่งออก XLSX จาก **ประวัติและรายงาน** โดยเลือกช่วงวันที่และพนักงาน รายการบนหน้าจอกับไฟล์ใช้ตัวกรองเดียวกัน ช่วงส่งออกสูงสุด 366 วัน ไฟล์มีชีตเดียว `Attendance_YYYYMMDD-YYYYMMDD` ตามแบบฟอร์ม Attendance 22 คอลัมน์ โดยมีแถวรายวันสำหรับพนักงานที่ใช้งานและแสดงวันหยุด/วันลา/ไม่พบเวลา มีรูปแบบวัน/เวลา/ชั่วโมงทำงานเป็นค่า Excel จริง และยังใช้ตัวกรองพนักงานที่เลือก
- หน้าตั้งค่าของผู้ที่เข้าสู่ระบบไม่แสดงเมนูเชื่อมต่อ Apps Script; ตั้งค่า URL ได้เฉพาะก่อนเข้าสู่ระบบ
- หน้าเข้าสู่ระบบมีตัวเลือก **จำการเข้าสู่ระบบบนเครื่องนี้** ที่เก็บ session token อายุสูงสุด 6 ชั่วโมงและรหัสพนักงานในเบราว์เซอร์ PIN อาจถูกบันทึกโดย password manager ของเบราว์เซอร์เมื่อรองรับ แอปไม่บันทึก PIN เป็นข้อความใน localStorage

## ข้อมูลใบหน้าและข้อจำกัด

`FaceTemplates` เก็บเวกเตอร์ตัวเลข 128 ค่าเป็น JSON ต่อพนักงานพร้อมสถานะและเวลาลงทะเบียน ไม่เก็บภาพถ่ายต้นฉบับ ทุกเครื่องอ่านชีตเดียวกันผ่าน Apps Script และการบันทึกเวลาใช้ LockService ป้องกันรายการชนกัน จำกัดสิทธิ์ Google Sheet ให้เฉพาะผู้ดูแล เพราะเวกเตอร์ใบหน้าเป็นข้อมูลอ่อนไหว

ระบบยังไม่มีการตรวจภาพปลอม/วิดีโอ (liveness) และ API หน้าสแกนร่วมไม่ต้องล็อกอิน ผู้ที่ได้เวกเตอร์อาจส่งซ้ำได้ จึงไม่ควรใช้เป็นหลักฐานยืนยันตัวตนที่มีความเสี่ยงสูงโดยไม่เพิ่มมาตรการป้องกัน การตรวจตำแหน่งผ่านเบราว์เซอร์อาศัยพิกัดที่อุปกรณ์ส่งมา จึงป้องกันการสแกนทั่วไปนอกพื้นที่ได้ แต่ไม่ป้องกันการปลอมพิกัดระดับอุปกรณ์ กล้อง เสียง และ GPS จริงต้องทดลองบน HTTPS ของอุปกรณ์ที่จะใช้ face-api.js และโมเดลโหลดผ่าน jsDelivr จึงต้องออนไลน์

## ตรวจระบบ

จากโฟลเดอร์ที่แตก ZIP:

```sh
node tests/backend-smoke.cjs
node tests/ui-smoke.cjs
node tests/face-smoke.cjs
node tests/api-smoke.cjs
```

ชุดนี้จำลอง Google Sheets และกล้องเพื่อทดสอบเส้นทางหลัก ยังต้องตรวจกล้อง เสียง สิทธิ์เบราว์เซอร์ และ Web App/Google Sheet จริงหลัง Deploy


## เวอร์ชัน 5.4.2 · การย้ายข้อมูลและการตั้งค่าเพิ่มเติม

การอัปเกรดนี้เพิ่มชีต Departments, AttendanceExceptions และ AttendanceKeys โดย setupAll() จะเพิ่มคอลัมน์และชีตที่ขาดโดยไม่ลบข้อมูลเดิม ตั้งค่า Late Grace Minutes เริ่มต้นเป็น 0 และเก็บ Application Enabled เป็น 1

แผนกเริ่มต้นคือ Office (วันหยุดหลักเสาร์และอาทิตย์) และ Warehouse (กำหนดวันหยุดได้ยืดหยุ่น) แผนกและวันหยุดหลักเก็บในชีต Departments ผู้ดูแล OWNER เปลี่ยนชื่อ/วันหยุดได้ การปิดใช้งานต้องย้ายพนักงานที่ยังใช้งานออกก่อน และลบได้เฉพาะแผนกที่ไม่มีแถวประวัติพนักงานอ้างอิง คำขอวันหยุดรายบุคคลยังผ่านสถานะรออนุมัติสำหรับพนักงาน ส่วนผู้ดูแลสามารถกำหนดวันหยุดให้ตนเองได้ทันที

ผู้ดูแลตั้งค่านาทีผ่อนผันก่อนนับว่าสายใน Config ผ่าน Late Grace Minutes ค่า 0 คือไม่มีเวลาผ่อนผัน

รหัส Developer สร้างแบบสุ่มพร้อม OWNER ระหว่าง `setupAll()` เก็บเฉพาะ salted hash ใน Script Properties และบังคับเปลี่ยนรหัสผ่านครั้งแรก เปิดเครื่องมือผ่าน URL ของเว็บที่ต่อท้าย `#developer` (เช่น `https://your-site.example/#developer`) ซึ่งไม่แสดงเป็นเมนูในหน้าพนักงานหรือผู้ดูแล หน้านี้เข้าได้แม้ปิดระบบหรือพ้นช่วงวันใช้งาน Developer ตั้งวันและเวลาเริ่ม/สิ้นสุดตามเขตเวลา Asia/Bangkok เปิด/ปิดการใช้งาน และเปิด/ปิด face scan ได้ เว้นวันเวลาไว้เพื่อไม่จำกัดช่วง ผู้ดูแลและ OWNER ยังเข้าสู่ระบบเพื่อดู/ส่งออกรายงานเมื่อระบบปิดหรือนอกช่วงได้ แต่ API ปฏิเสธการแก้ไขข้อมูลทุกชนิด ฝั่งพนักงานไม่สามารถเข้าสู่ระบบหรือสแกนในช่วงดังกล่าวได้

การยื่นคำขอลงเวลาแทนใบหน้าจาก kiosk ใช้รหัสพนักงาน เหตุผล เวลาอ้างอิง และ GPS ภายในพื้นที่ทำงาน โดยไม่ขอ PIN คำขอจะอยู่ใน `AttendanceExceptions` และยังไม่สร้างรายการ Attendance จนกว่าหัวหน้างานหรือ OWNER จะตรวจและอนุมัติ ผู้ที่เข้าสู่ระบบยื่นจากเซสชันเดิมได้ ระบบจำกัดจำนวนคำขอและบันทึก audit trail

ประวัติและ export โหลดจาก Apps Script ด้วยช่วงวันที่ (สูงสุด 366 วัน) แทนการส่งประวัติทั้งหมดให้หน้าเว็บ ส่งออก XLSX เป็นชีตเดียวตามรูปแบบแบบฟอร์ม Attendance มี 22 คอลัมน์ แถวหัวตารางคงที่ และรูปแบบวันที่/เวลา/ระยะเวลาทำงานแบบ Excel; ค่าเริ่มต้นให้พนักงานเห็นข้อมูลตัวเอง Admin/OWNER เลือกเปิดข้อมูลของพนักงานที่ระบุได้ แผนกจัดการโดย OWNER; ใช้ปิดใช้งานแทนการลบเพื่อเก็บความเชื่อมโยงย้อนหลัง หมายเหตุพนักงานเก็บในคอลัมน์ใหม่ที่ setup เพิ่มต่อท้าย schema เดิม

OT ใช้ค่าเริ่มต้นคำนวณตามเวลาจริง เลือกปัดลงเป็นช่วงละ 30 นาทีได้ในนโยบายระบบ การเปลี่ยนนโยบายไม่แก้ค่าประวัติที่บันทึกแล้ว เวลาผ่อนผันก่อนนับสายยังตั้งได้จาก `Late Grace Minutes` ค่าตั้งต้น 0 นาที

การส่งยืนยันการสแกนใช้คีย์ idempotency ที่เก็บใน localStorage ร่วมกับ pending token, รหัสพนักงาน, ชื่อ และเวลาเริ่มคำขอเท่านั้น ไม่มีการเก็บภาพหรือเวกเตอร์ใบหน้าใน outbox การยืนยันที่เซิร์ฟเวอร์รับแล้วตอบซ้ำอย่างปลอดภัยเมื่อใช้คีย์เดิม pending token มีอายุ 10 นาทีตาม cache ของ Apps Script จึงต้องส่งซ้ำก่อน token หมดอายุ หากหมดอายุให้สแกนใหม่และติดต่อ Admin หากไม่แน่ใจว่ารายการถูกบันทึกหรือไม่

ข้อจำกัดของรุ่นนี้: การเทียบใบหน้าในหน้าสแกนยังทำที่ Apps Script และยังไม่มี roster/vector cache ในหน้าเว็บ การเปิดเผยเวกเตอร์ทั้งหมดให้ kiosk ที่ไม่ได้ยืนยันบัญชีถูกปฏิเสธโดยการตรวจทานความปลอดภัย เพราะเสี่ยงเปิดเผยข้อมูล biometric; ต้องมีรูปแบบ kiosk ที่เชื่อถือได้และยืนยันตัวตนก่อนจึงจะทำ local matching ได้ เครื่องมือ Developer เปิดด้วยการเติม `#developer` ต่อท้าย URL โดยไม่มีปุ่มบนหน้าสแกนหรือเมนูผู้ดูแล แบบฟอร์มยื่นข้อยกเว้นตรวจรหัสพนักงานและตำแหน่ง ณ จุดทำงาน พร้อมหน้าพิจารณาสำหรับ Admin ข้อจำกัดเพิ่มเติม: การตรวจ geofence ไม่ผูกกับฮาร์ดแวร์เครื่องใดเครื่องหนึ่ง จึงควรจำกัดการเข้าถึงเครื่องที่กำหนดและทดสอบบนอุปกรณ์จริงก่อนเปิดใช้งาน


รุ่น 5.4.2.1 (ต้อง deploy Apps Script เวอร์ชันใหม่หลังแทนที่ไฟล์; ไม่มีคอลัมน์ชีตใหม่): ปฏิทินทีมแสดงชื่อและเหตุการณ์ที่จำเป็นของพนักงานที่ใช้งานทุกคน โดยไม่เปิดประวัติลงเวลาแบบละเอียดให้พนักงานอื่น; สรุป OT แสดงเป็นตารางแยกตามอัตราพร้อมเวลาทำงานสุทธิหลังหักพักและช่วงวันที่; การยืนยันหลังสแกนใช้ค่าตำแหน่งที่ตรวจแล้วในหน่วยความจำชั่วคราวไม่เกิน 2 นาทีเพื่อลดคำขอซ้ำ แต่เซิร์ฟเวอร์ยังตรวจ geofence ทุกครั้ง; XLSX ใช้รูปแบบชีต Attendance ตามแบบฟอร์มที่อ้างอิง (วัน/เวลา/ชั่วโมงทำงานเป็นค่า Excel ที่มีชนิดข้อมูลและรูปแบบเซลล์) เวลาทำงานยังหักเวลาพักตามกะเดิม


## เวอร์ชัน 5.4.2.2 · คำขอลงเวลาและหน้าสแกน

คำขอลงเวลาแทนใบหน้าบันทึกเวลาที่อ้างอิงและเวลาส่งคำขอเป็นค่า Date ของ Google Sheets พร้อมรูปแบบ `dd/MM/yyyy HH:mm:ss` (เขตเวลา Asia/Bangkok) โดย API และ audit trail ยังคงส่งค่าเวลาแบบ ISO ที่มีเขตเวลาเพื่อเก็บความแม่นยำและความหมายเดิม เมื่อรัน `setupAll()` ระบบแปลงเฉพาะข้อความ ISO ที่มี `Z` หรือ offset `±HH:mm` ในคอลัมน์เวลาที่อ้างอิง เวลาส่งคำขอ และเวลาพิจารณา ค่าอื่นที่กำกวมจะไม่ถูกแก้ไข ข้อมูลเหตุผล ผลพิจารณา ผู้พิจารณา รหัสรายการ และ audit trail ยังคงเดิม การรันซ้ำปลอดภัย

เมื่อ Admin อนุมัติคำขอ ระบบสร้างรายการ Attendance ที่ยังเปิดอยู่ตามเวลาอ้างอิง และแสดงเวลาออกงานเป็น “รอออกงาน” พนักงานใช้การสแกนใบหน้าตามปกติเพื่อออกงานในแถวเดิม ซึ่งเชื่อมโยงกับคำขอและบันทึกเวลาทำงาน/OT เมื่อมีคำขอแทนใบหน้าที่ยังรออนุมัติและไม่มีรายการเปิดอยู่ ระบบจะปฏิเสธการยืนยันสแกนก่อนสร้างรายการเข้างานใหม่ พร้อมข้อความให้รอผู้ดูแลพิจารณา

การเปิดแบบฟอร์มลงเวลาแทนจะปิดกล้องและยกเลิกผลระบุตัวตนที่มาถึงภายหลัง ต้องกดเริ่มสแกนอีกครั้งหลังปิดแบบฟอร์ม กล้องแสดงสถานะตรวจสอบใบหน้าแยกจากสถานะว่าง ปุ่มยืนยันจะแสดงสถานะบันทึกทันที; เมื่อเครือข่ายขัดข้องจะเก็บ pending token เดิมไว้ให้ส่งซ้ำ ส่วนปุ่มปฏิเสธยกเลิก token แล้วเริ่มการสแกนใหม่

หน้า Home ของผู้ดูแลแสดงรายการคำขอแทนใบหน้าที่รอพิจารณา ธีมสว่าง/มืดใช้ชุดสีร่วมกันทุกหน้าจอ เลือกตามค่าระบบปฏิบัติการครั้งแรกและจดจำค่าที่เลือกใน localStorage ของเบราว์เซอร์ แบบฟอร์มใช้ป้ายกำกับ “รหัสพนักงาน”, “เวลาที่อ้างอิง” และ “หมายเหตุ” และไม่ขอ PIN

ทดสอบด้วย `node tests/backend-smoke.cjs`, `node tests/ui-smoke.cjs`, `node tests/face-smoke.cjs` และ `node tests/api-smoke.cjs` ก่อน Deploy เวอร์ชัน Apps Script ใหม่และเผยแพร่หน้าเว็บ


### การกู้คืนรายการสแกนที่ยังไม่ทราบผล

ระบบเก็บ confirmation ได้ครั้งละหนึ่งรายการ เพื่อไม่ให้การสแกนคนถัดไปเขียนทับรายการที่เซิร์ฟเวอร์อาจบันทึกแล้ว เก็บเฉพาะ route (`publicConfirm` หรือ `confirmFace`), pending token, รหัสพนักงาน/ชื่อ และ idempotency key; ไม่เก็บ PIN หรือ session token ใน outbox หากการตอบกลับขาดหาย ปุ่มยืนยันจะกลายเป็น “ส่งซ้ำเพื่อบันทึกเวลา” และส่งด้วย route, pending token และคีย์เดิมจนกว่าเซิร์ฟเวอร์ยืนยันผล การยกเลิก การเปิดแบบฟอร์มลงเวลาทดแทน การระบุตัวตนใหม่ และการเริ่มรายการของพนักงานคนอื่นจะถูกพักไว้ระหว่างนี้ รายงาน การตั้งค่า และหน้า Developer ยังใช้งานได้ตามสิทธิ์เดิม

เมื่อเปิดแอปใหม่ รายการ kiosk จะกลับมาในหน้าสแกนเดิม ส่วนรายการจากหน้าสแกนหลังเข้าสู่ระบบจะขอให้เข้าบัญชีพนักงานรหัสเดิมก่อนส่งซ้ำ ถ้า Apps Script ยืนยันว่า token หมดอายุและไม่มีรายการถูกบันทึก ระบบจะปลดล็อกและให้สแกนใหม่ได้ การปฏิเสธก่อนเขียนที่ระบบระบุได้ชัดเจน เช่น มีคำขอเวลาสำรองรออนุมัติ จะปลดล็อกอย่างปลอดภัย ส่วนข้อผิดพลาดเครือข่ายหรือคำตอบที่ยังยืนยันไม่ได้จะคงรายการไว้และห้ามเริ่มรายการใหม่


### ปรับการอ่านตำแหน่ง GPS
ใช้ตำแหน่งที่อ่านสำเร็จครั้งล่าสุดเป็นเวลา 10 นาทีในหน่วยความจำของหน้าเว็บ รวมทั้งการสแกน ยืนยัน และยื่นคำขอลงเวลา โดยยังตรวจพื้นที่กับเซิร์ฟเวอร์ เมื่อครบ 10 นาทีจะอ่านตำแหน่งใหม่ในการใช้งานครั้งต่อไป ปิดหรือรีเฟรชหน้าเว็บจะล้างแคช ไม่เก็บตำแหน่งถาวรในเครื่อง


## เวอร์ชัน 5.4.2.3 · สแกนต่อเนื่องบนเครื่องส่วนกลาง

### ติดตั้ง
อัปโหลดโฟลเดอร์ public ใหม่ไปยังโฮสต์ และเพิ่มไฟล์ apps-script/Continuous.gs พร้อมอัปเดต Code.gs และ Attendance.gs รวมทั้งไฟล์ Apps Script อื่นจากชุดนี้ จากนั้น Deploy Apps Script เป็นเวอร์ชันใหม่ โดยคง URL /exec เดิมได้ ฐานข้อมูลใช้ชีตเดิม ไม่ต้องล้างหรือสร้างใหม่ และไม่ต้องรัน setupAll ใหม่เพื่อใช้ฟีเจอร์นี้ สำรองชีตก่อนอัปเดตตามปกติ

### เปิดใช้งาน
1. ใช้เครื่องส่วนกลางที่บริษัทควบคุม เข้าสู่ระบบ Owner หรือ Admin
2. ไปหน้าตั้งค่า > เครื่องสแกนส่วนกลาง > เปิดโหมดสแกนต่อเนื่องบนเครื่องนี้
3. ระบบตรวจตำแหน่งและโหลดรายชื่อ/เวกเตอร์เข้า RAM จากนั้นออกจากบัญชี Admin กลับหน้าสแกน ข้อมูลใบหน้าไม่เก็บใน localStorage หรือคิว
4. จับคู่ใบหน้าบนเครื่องด้วยเกณฑ์ระยะเดิมและส่วนต่างอันดับหนึ่ง/สอง 0.08 ไม่บังคับรอ 5 วินาทีก่อนจับภาพ
5. กด “ใช่ ฉันเอง” จะเก็บรายการในคิวให้สำเร็จก่อน เปิดให้คนถัดไปสแกน โดยไม่ต้องรอผลเขียนชีต พร้อมส่งทีละรายการตามลำดับเบื้องหลัง
6. สถานะ “รอส่ง” ยังไม่ใช่การบันทึกสำเร็จ เมื่อ Apps Script ตอบรับจึงแสดง “บันทึกสำเร็จ”

### คิวและเวลา
- คิว localStorage แยกตาม URL ของ Apps Script มีรหัส idempotency ต่อรายการ และใช้ Web Locks ป้องกันการส่งหลายแท็บพร้อมกัน เบราว์เซอร์ต้องรองรับ Web Locks (HTTPS)
- เก็บรหัส/ชื่อพนักงาน เวลายืนยัน ประเภทเข้าออก ตำแหน่ง รหัสรายการ และบัตรสิทธิ์ที่เซิร์ฟเวอร์เซ็น ไม่มีรูป เวกเตอร์ PIN หรือเซสชัน Admin ในคิว
- เวลาใช้เวลาเซิร์ฟเวอร์ที่โหลดตอนเปิดโหมดบวกเวลาที่ผ่านไปบนเครื่อง ไม่ใช้เวลาที่ชีตเขียนสำเร็จมาคิดสาย/ทำงาน/OT หักพักแบบเดิม
- คิวคงอยู่หลังรีเฟรช และลองส่งเมื่อเปิดเว็บอีกครั้ง/เน็ตกลับมา/ทุก 15 วินาที แต่การส่งขณะปิดเว็บไม่ได้รับประกัน ต้องเปิดหน้าเว็บให้ส่งจนสำเร็จ ห้ามล้างข้อมูลเว็บไซต์ก่อนคิวหมด
- จำกัด 200 รายการรอส่ง พนักงานคนเดียวมีรายการรอได้หนึ่งรายการ และกันยืนยันซ้ำภายใน 1 นาที คิวที่ส่งไม่ผ่านจะหยุดรอที่หัวคิวเพื่อรักษาลำดับ
- หากหัวคิวมีปัญหา ให้ Admin เข้าหน้าตั้งค่า ตรวจสาเหตุ แล้วกดตรวจสอบ/ยกเลิกรายการ เซิร์ฟเวอร์จะตรวจผลเดิมก่อน ถ้ายังไม่บันทึกจะสร้างหลักฐานยกเลิกกันคำขอเก่าที่มาช้าบันทึกตามหลัง ไม่ลบทิ้งคิวแบบไม่ตรวจสอบ
- แสดงผลสำเร็จล่าสุด 20 รายการในเครื่อง รายการรอจะไม่ถูกลบทิ้งอัตโนมัติ
- แคช GPS 10 นาทีตามรุ่นก่อนยังคงใช้ เมื่อหมดอายุแล้วต้องอ่านใหม่ครั้งถัดไป

### สิทธิ์และข้อจำกัด
โหมดนี้เป็นการจับคู่ใบหน้าโดยเครื่องส่วนกลางที่ Admin อนุญาต จึงต้องใช้บนเครื่องที่บริษัทดูแล เซิร์ฟเวอร์ตรวจลายเซ็นสิทธิ์ ผู้อนุญาตยังมีสิทธิ์ สถานะพนักงาน/ใบหน้าปัจจุบัน การเปิดระบบโดย Developer พื้นที่ เวลา และสถานะรายการเข้าออกก่อนบันทึก ผลระยะเทียบใบหน้ามาจากเครื่องส่วนกลาง ไม่ใช่การตรวจใบหน้าซ้ำบนเซิร์ฟเวอร์ และไม่มีการตรวจ liveness

สิทธิ์โหมดใช้ได้ 6 ชั่วโมง ปิดหรือรีเฟรชทำให้รายชื่อและเวกเตอร์ใน RAM หาย ต้องให้ Admin เปิดโหมดใหม่ คิวที่ยังไม่ส่งเมื่อสิทธิ์หมดอายุจะคงอยู่ให้ Admin ตรวจสอบ ไม่รับบันทึกอัตโนมัติแบบข้ามการหมดอายุ เมื่อเพิ่ม/ลบ/เปลี่ยนข้อมูลใบหน้าหรือมีการลงเวลาจากเครื่องอื่น ให้ส่งคิวเดิมจนหมดและเปิดโหมดใหม่เพื่อโหลดข้อมูลล่าสุด ถ้าสถานะไม่ตรง เซิร์ฟเวอร์จะพักรายการเพื่อให้ Admin ตรวจสอบ

หากไม่เปิดโหมดนี้ หน้าสแกนเดิมและหน้าสแกนหลังเข้าสู่ระบบยังใช้การตรวจใบหน้าบนเซิร์ฟเวอร์และรอผลยืนยันแบบเดิม

ตรวจ syntax ของ JavaScript/Apps Script แล้ว ยังไม่ได้ทดสอบกับกล้อง GPS หรือ Apps Script จริง และไม่ได้ Deploy ให้
